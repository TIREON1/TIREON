# 앱 셸 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 네 목적지를 가진 Compose 앱 셸과 반응형 레이아웃을 세우고, ViewModel을 `:app`으로 옮긴다.

**Architecture:** `MainActivity` 하나에 `NavHost`로 home, practice, report, settings를 둡니다. 화면은 얇게 유지하고 상태는 ViewModel에서 옵니다. portrait과 landscape를 모두 설계하고 `WindowSizeClass`로 분기합니다.

**Tech Stack:** Compose Material3, Navigation Compose, lifecycle-viewmodel-compose, JUnit

**Spec:** `docs/design/app-foundation-design.md` (4장 화면 구조, 6.4 기존 코드 정리)

## Global Constraints

- SDK 타입을 `:app`으로 노출하지 않습니다. `:pleos`가 제공하는 도메인 타입만 씁니다.
- 화면 텍스트는 `strings.xml`에 둡니다. 하드코딩하지 않습니다.
- 측정 불가를 0으로 표시하지 않습니다. 값이 없으면 "사용할 수 없음"으로 보여줍니다.
- 주행 중 노출 화면은 숫자 하나만 표시합니다.
- 커밋 메시지는 `type: 한국어 내용` 형식을 따릅니다.
- 검증 명령: `./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug`

## Review Focus

1. 값이 없는 상태에서 화면이 깨지는 경우. 속도나 점수가 `null`일 때 크래시 없이 안내 문구가 나와야 합니다.
2. 창 크기가 바뀌는 경우. portrait과 landscape를 오갈 때 상태가 유지되어야 합니다.
3. 목적지를 빠르게 전환하는 경우. 백스택이 쌓여 뒤로 가기가 이상하게 동작하지 않아야 합니다.
4. 점수가 데이터 부족 상태인 경우. 0점과 구분되어 표시되어야 합니다.
5. ViewModel을 옮긴 뒤 기존 화면이 계속 동작하는지.

### Task 2: 화면 상태 모델

**Files:**
- Create: `app/src/main/kotlin/ai/tireon/app/home/HomeUiState.kt`
- Test: `app/src/test/kotlin/ai/tireon/app/home/HomeUiStateTest.kt`

**Interfaces:**
- Consumes: `:core`의 `ScoreResult`, `InsufficientReason`
- Produces:
  ```kotlin
  data class HomeUiState(
      val scoreText: String?,      // null이면 표시할 점수 없음
      val statusText: String,      // 항상 표시
      val hasScore: Boolean,
  )
  ```

문구를 화면에서 만들지 않고 상태에서 만듭니다. 단위 테스트가 가능해집니다.

- [ ] **Step 1: 테스트를 쓴다 (실패 예정)**

```kotlin
package ai.tireon.app.home

import ai.tireon.core.DrivingScore
import ai.tireon.core.analysis.InsufficientReason
import ai.tireon.core.analysis.ScoreResult
import kotlin.test.Test
import kotlin.test.assertEquals
import kotlin.test.assertFalse
import kotlin.test.assertNull
import kotlin.test.assertTrue

class HomeUiStateTest {

    @Test
    fun `점수가 있으면 숫자를 보여준다`() {
        val state = HomeUiState.from(ScoreResult.Scored(DrivingScore(85), emptyList()))

        assertEquals("85", state.scoreText)
        assertTrue(state.hasScore)
        assertEquals("오늘의 운전 점수", state.statusText)
    }

    @Test
    fun `데이터가 부족하면 점수 대신 이유를 보여준다`() {
        val state = HomeUiState.from(
            ScoreResult.Insufficient(InsufficientReason.DISTANCE_TOO_SHORT),
        )

        assertNull(state.scoreText)
        assertFalse(state.hasScore)
        assertEquals("조금 더 길게 주행하면 점수를 낼 수 있어요", state.statusText)
    }

    @Test
    fun `샘플 부족은 신호 문제로 안내한다`() {
        val state = HomeUiState.from(
            ScoreResult.Insufficient(InsufficientReason.NOT_ENOUGH_SAMPLES),
        )

        assertEquals("차량 신호를 충분히 받지 못했어요", state.statusText)
    }

    @Test
    fun `주행 기록이 없으면 시작을 안내한다`() {
        val state = HomeUiState.empty()

        assertNull(state.scoreText)
        assertFalse(state.hasScore)
        assertEquals("아직 주행 기록이 없어요", state.statusText)
    }
}
```

- [ ] **Step 2: 실패를 확인한다**

Run: `./gradlew :app:testDebugUnitTest --tests '*HomeUiStateTest*'`
Expected: FAIL. `HomeUiState` 미정의

`from(ScoreResult)`과 `empty()`를 만듭니다. `Insufficient` 사유별 문구는 `when`으로 나눕니다.

- [ ] **Step 4: 통과를 확인한다**

Run: `./gradlew :app:testDebugUnitTest --tests '*HomeUiStateTest*'`
Expected: PASS (4 tests)

- [ ] **Step 1: 테스트를 쓴다 (실패 예정)**

```kotlin
package ai.tireon.app.ui

import kotlin.test.Test
import kotlin.test.assertEquals

class WindowLayoutTest {

    @Test
    fun `좁은 창은 단일 열이다`() {
        assertEquals(WindowLayout.COMPACT, WindowLayoutPolicy.of(360))
        assertEquals(WindowLayout.COMPACT, WindowLayoutPolicy.of(599))
    }

    @Test
    fun `넓은 창은 두 열이다`() {
        assertEquals(WindowLayout.EXPANDED, WindowLayoutPolicy.of(600))
        assertEquals(WindowLayout.EXPANDED, WindowLayoutPolicy.of(1280))
    }

    @Test
    fun `경계값은 확장으로 본다`() {
        assertEquals(WindowLayout.EXPANDED, WindowLayoutPolicy.of(600))
        assertEquals(WindowLayout.COMPACT, WindowLayoutPolicy.of(599))
    }
}
```
