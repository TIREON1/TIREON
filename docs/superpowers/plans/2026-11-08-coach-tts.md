# 코치 TTS 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 코칭 문장을 오프라인 음성으로 읽어준다. TTS가 실패해도 화면은 정상 동작한다.

**Architecture:** `:core`의 `CoachMessages`가 문장을 만들고, `:pleos`의 `CoachSpeaker`가 읽습니다. 재생 간격과 중복 억제는 순수 함수로 분리해 JVM에서 시험합니다.

**Tech Stack:** Pleos TextToSpeech SDK 3.3.1, `Mode.ON_DEVICE`

**Spec:** `docs/design/app-foundation-design.md` (7.4 TTS)

## Global Constraints

- `Mode.ON_DEVICE`를 씁니다. 네트워크와 앱 등록이 필요 없습니다.
- 권한 `pleos.car.permission.TTS_SERVICE`를 선언합니다.
- SDK 타입을 `:app`으로 노출하지 않습니다. 인터페이스만 공개합니다.
- TTS 실패는 조용히 무시합니다. 음성은 보조 수단이고 화면이 주 경로입니다.
- 백그라운드 진입과 화면 종료 시 반드시 `stop()`과 `release()`를 호출합니다.
- 커밋 메시지는 `type: 한국어 내용` 형식을 따릅니다.
- 검증 명령: `./gradlew assembleDebug test lint`

## Review Focus

1. TTS 초기화가 실패하는 기기. 앱이 멈추지 않고 화면만 동작해야 합니다.
2. 문장이 연속으로 발생하는 경우. 말이 겹치지 않아야 합니다.
3. 앱이 백그라운드로 갈 때. 재생이 멈춰야 합니다.
4. 리소스 해제 누락. TTS 엔진이 남아 있으면 배터리를 소모합니다.
5. 한국어가 아닌 기기. `ko-KR`을 명시하면 기기 언어와 무관하게 동작해야 합니다.

    @Test
    fun `같은 문장은 간격이 지나도 다시 읽지 않는다`() {

            SpeechPolicy.shouldSpeak(10_000L, 1_000L, "출발 좋아요", "출발 좋아요"),
        )
    }

    @Test
    fun `빈 문장은 재생하지 않는다`() {
        assertFalse(SpeechPolicy.shouldSpeak(10_000L, 0L, "   ", null))
    }
